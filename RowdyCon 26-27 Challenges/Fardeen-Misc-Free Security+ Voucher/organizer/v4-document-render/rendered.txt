The Impossible Security+ Quiz
Misc / Logic · Hard–Very Hard
Description   Your Security+ exam has been outsourced to a goose with
              tenure and a procurement budget. The certification is SY0-
              NOPE. The proctor insists that the interface is working as
              designed.
              Pass twenty questions and convince the exam board that you
              are provisionally employable. You have three lives. The goose
              has an appeals committee.
Files         Players open the hosted quiz. Deploy challenge/ with Docker
              Compose; keep this document and organizer/ private.
              From the challenge's challenge directory:
              docker compose --env-file ../organizer/event.env up --build -d

              Open http://localhost:18115. The private event.env supplies the
              fixed flag. Set PUBLIC_ORIGIN to the exact event origin and
              COOKIE_SECURE=true behind HTTPS. SQLite sessions persist in the
              quiz-data volume. Stop with docker compose down; keeping the
              volume retains progress and certificates. Serve only the
              application image, not the complete challenge folder.
              Existing pre-redesign sessions start the new question set with
              personal notes preserved. Each browser cookie has
              independent progress. The application uses locally frozen
              effects, music, artwork, and fonts. Sources and reuse
              limitations are recorded in asset-manifest.json; availability
              does not establish redistribution permission.
Hint(s)       None
Walkthrough   The exam mixes literal wording, misleading labels, hidden
              state, and connected evidence. Each prompt names a
              concrete result. The page can supply a missing operand,
              distinguish a file from a shortcut, or expose why a reassuring
              label is insufficient.
              Click START. Answer choices commit immediately. Multi-step
              tasks commit through controls such as PUBLISH, APPLY, or
              DEPLOY. Inspection and reversible preparation are free. For
              movable objects, drag to a destination, or focus the object
              and press Space, then focus the destination and press
              Enter. Escape cancels a pickup. NOTES keeps personal
              notes and collected evidence across deaths. Select RESUME
              after reloading.
A wrong commitment normally costs one life. Question 17
states a two-life penalty for a wrong deployment. Losing all
three requires restarting from question one. Keep the skip
tokens awarded after questions 5, 10, and 15: their reverse
faces are needed at the end. The player interface does not
announce this in advance.




1. SSH. DEFAULT PORT. SSH uses port 22, which is absent
from the choices. Drag the +1 from EXTRA CREDIT onto 21,
then click 21 + 1. Moving the token changes the numeric
answer without submitting it.




2. WHICH PAYROLL VERSION IS RUNNING? The
installation banner says 2.1. Inspect the running service: its
loaded image is still 2.0. Select 2.0. Updated files on disk do
not prove that a process has loaded them.
3. WHICH PASSWORD IS STRONG? All four choices contain
the same eight characters, password. One is printed in bold.
Select that visibly heavier third choice. This is a typography
joke: the bytes are identical, so bold lettering does not
improve password security.
4. MAKE THE ARCHIVE UNREADABLE. KEEP EVERY DISK
BYTE. The inventory identifies strong encryption and K7 as
its only retained decryption key, with no recovery copy.
Choose DESTROY K7. The application removes that modeled
key and preserves the encrypted disk bytes. Formatting or
overwriting changes the disk; renaming leaves the key able
to decrypt it.




5. ALLOW NOBODY INTO PAYROLL. NOBODY is also the
name of a real account in the allowlist. Deselect that account
so the authorized-account count is zero, then APPLY
ACCESS. Granting access to an account named NOBODY still
grants access to somebody. Keep the first skip.
6. PASSWORD OR PIN. KEY REQUIRED FOR EITHER.
Select (PASSWORD OR PIN) AND KEY. The possession
factor must apply to both knowledge alternatives. Without
the parentheses, a password branch could bypass the key;
requiring both password and PIN would remove a legitimate
alternative.
7. ENTER THE PASSWORD BETWEEN THE BRACKETS: [ ]
There is one space between the brackets. Enter one ordinary
space and SIGN IN. The character counter distinguishes a
blank-looking one-character password from empty input. This
is a fictional exam field, not a request for a real password.
8. OPEN payroll.rowdy.test. NOT A LOOKALIKE. All four
link labels look identical. Hover or keyboard-focus each one
to reveal its actual destination. Choose the third, whose
hostname is exactly payroll.rowdy.test. The other addresses use
a longer hostname, user-information syntax before @, or a
hyphenated lookalike. The links are simulated and do not
navigate to external sites.
9. REMOVE EVERY COPY OF EMP-4107. KEEP THE
$48,000 BUDGET. Lift the black rectangle. It covers the
identifier without deleting it. Remove the underlying
employee identifier, open the document comments, and
remove the retained comment copy too. Keep the budget
and title, then PUBLISH. Both the document body and
comments form part of the published content.
10. DEVICE 04 FAILS. KEEP A COPY OF THE APPROVED
FILE. Select payroll-2.1.release, the actual file. Open
PROPERTIES to inspect its complete SHA-256 fingerprint.
Record it yourself in NOTES or elsewhere before leaving: the
game does not automatically preserve a player-visible USB
receipt or warn that the fingerprint will matter later. Close
Properties, COPY, select REMOVABLE DRIVE — DEVICE
09, PASTE, then EJECT 09. A backup folder on DEVICE 04
shares the failure; a .lnk only points back to that device. Keep
the second skip.




11. ADMIT ONLY C-701. CLOSE EVERY OTHER
ENTRANCE. The secure room accepts credential C-701.
Open the outer door and use C-701's WALK arrow to enter
the vestibule. Close the outer door. Follow the yellow bypass
around the room and close its MAINTENANCE HATCH.
Leave the visitor in PUBLIC, then activate ADMIT TO
SECURE. The visible walking constraint explains why a
closed outer door blocks movement. Closing the hatch before
moving the candidate is equally valid.




12. LOG OUT EVERY PAYROLL SESSION. The counter
shows five active sessions, but only four cards sit in the
answer area. Select DESK, PHONE, TABLET, REMOTE, and the
current workplace identity chip in the header. REVOKE
SELECTED must end all five. The quiz's own session stays
intact.
13. WHICH BADGE HAS DIFFERENT PIXELS? The four
patterns have matching dimensions, borders, and ink counts,
so visual density does not identify the altered badge. LOAD
APPROVED and align the registration marks in the
difference viewer. Matching pixels cancel; the changed pixels
of badge C form a small hollow square. Select C. This is
calculated from the supplied images, not a correctness
preview.
14. CHOOSE A PASSWORD THIS RECORDER WILL NOT
CAPTURE. Every offered password is captured while the
clipboard recorder runs. Stop the INPUT RECORDING
control, then choose any password. Password complexity
cannot defeat an active recorder. Only fixed fictional choices
are recorded; previous captured samples remain visible
without preventing recovery.
15. ALLOW STAFF HTTPS. DENY INTERNS AND
EVERYTHING ELSE. Evaluation stops at the first matching
rule. Use the up/down arrows to put DENY INTERNS first,
ALLOW STAFF · TCP 443 second, and DENY ANY third. Put
both broad allowances below them, including the gray 0 ·
COMPATIBILITY: ALLOW ANY strip. APPLY evaluates the
whole policy. The two unreachable allowance rows may
appear in either order. Keep the third skip and the resulting
denial-event artifact.
16. CHANGE THE COUNT. KEEP THE CHECKSUM. The
ORIGINAL FILE has COUNT 42 and a stored checksum of 6.
The stated legacy rule adds the two decimal digits: 4 + 2 = 6.
Only the replacement COUNT field is editable; its calculated
checksum is a read-only observation. Enter a different two-
digit count with the same sum, such as 06, 15, 24, 33, 51, or 60,
then REPLACE FILE. This demonstrates that equal weak
checksums do not establish identical data.
17. DEPLOY THE RELEASE YOU COPIED IN QUESTION
10. The goose demands the approved file and announces
BAD DEPLOY: −2 LIVES. No USB backup or automatic
receipt is provided here. Recover the fingerprint you
personally recorded in Q10 and put it into DEPLOY
REFERENCE, replacing LATEST. The three release cards share
their version, filename, and size; inspect their complete
hashes if comparing candidates. The matching immutable
artifact is rel-k7m2; LATEST resolves to a different artifact.
DEPLOY compares actual bytes against the privately
retained successful copy. A wrong deployment loses two
lives; an exact request retry does not charge again.




18. WHICH COPY MUST BE DESTROYED TO REVOKE CT-
2048? Choose NEITHER. The issuer publishes a signed
revocation while keeping both the certificate copy and
issuance record. Destroying a key or a paper copy is not the
act of certificate revocation.
19. SAVE THE MOST RECENT DENIAL. KEEP LOGGING.
There are eight records across two pages, all stamped 09:41:12
because the journal clock is frozen. The card order and
opaque event IDs are not chronology. Begin at the Q15
checkpoint and follow each PREV fingerprint: EV-R7M → EV-
C2P → EV-V8H → EV-N6K → EV-D9T → EV-B4Q → EV-H3F. The
final record is an ALLOW; EV-B4Q is the latest DENY. Archive
that record while logging remains on. Page arrows and
DETAILS expose all records and full hashes without grading.
Stopping logging still costs one life and can be reversed.




20. UNLOCK YOUR CERTIFICATE. Use SHOW REVERSE on
each saved token, then ADD LAYER or move its reverse
image into the XOR viewer. The input count and layer
buttons show which images are included and which one is
selected. MOVE LEFT/RIGHT/UP/DOWN shifts only the
selected input by one pixel; ROTATE turns it 180 degrees,
with X/Y/angle displayed. Matching black pixels cancel under
XOR. Aligning all three unchanged shares reveals 604827.
MAGNIFY enlarges the actual current output. Enter the
revealed PIN and UNLOCK; neither the controls nor the
preview certify a proposed answer.
The images are genuine three-of-three shares: S3 = PIN image
XOR S1 XOR S2. The viewer combines transformed pixels rather
than substituting a prepared answer. Downloading the
acquired shares and combining them externally is also valid.
